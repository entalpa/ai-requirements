# The AI-Driven Development (ADD) Manifesto

> **Software is no longer just written; it is co-authored.**
> 
> The traditional Agile model was designed for humans talking to humans. In the era of Vibe Coding and Autonomous Agents, the "human-to-machine" handoff is where projects succeed or fail. We believe a new framework is required.

---

### I. Requirements are the New High-Level Language
In the past, code was the source of truth. In ADD, **specifications are the source of truth.** If an AI can generate a thousand lines of code in seconds, the value of the human developer shifts from *writing* the syntax to *governing* the intent. 
* **The Principle:** Do not debug code; debug the requirements that generated it.

### II. Rigor Over "Vibes"
"Vibe coding" is a superpower, but vibes don't scale. An AI agent is only as competent as the context it is given. Without structure, "vibes" lead to technical debt and hallucinated logic.
* **The Principle:** Structure is the "Context Anchor" that prevents AI drift. A precise requirement is a directive; a vague prompt is a gamble.

### III. Traceability is the Safety Net
In traditional development, documentation often rots. In AI-Driven Development, documentation is a living map. Every function, every test, and every UI component must be traceable back to a human-verified User Story.
* **The Principle:** If you can’t trace a feature back to its requirement, you don’t own your software—the AI does.

### IV. The Socratic Loop (The Maieutic Method)
AI should not be a passive scribe. It should be an active challenger. The best specifications are not dictated; they are elicited through a dialogue between human creativity and machine logic.
* **The Principle:** Use AI to find the gaps in your thinking before you use it to write the code.

### V. Declarative Architecting
We move from *Imperative Programming* (telling the computer *how* to do it) to *Declarative Architecting* (defining *what* the system must be). The architect’s role is to define the constraints, the stakeholders, and the acceptance criteria.
* **The Principle:** Focus on the "What" and the "Why." Let the agents handle the "How."

---

## How to Practice ADD
1.  **Define the Actors:** Use AI to identify every stakeholder, from the end-user to the database admin.
2.  **Stress-Test the Idea:** Run your concept through a "Devil's Advocate" agent to uncover edge cases.
3.  **Modularize Early:** Break monolithic "vibes" into discrete subsystems.
4.  **Execute via MCP:** Feed verified specs into your IDE via Model Context Protocol (MCP) to ensure the AI coder never loses the plot.
